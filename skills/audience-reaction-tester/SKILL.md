# 가상 시청자 반응 테스트

콘텐츠를 만들기 **전에** 후보(주제·제목·썸네일 문구·훅)를 가상 시청자들에게 보여주고,
누가 클릭할지·왜 넘길지를 미리 확인하는 스킬이다.
MiroFish 같은 대규모 시뮬레이션 없이, 몇 초 만에 "어느 안이 더 나은가"를 판단하는 것이 목적이다.

사용자는 초보자일 수 있다. 전문 용어(CTR, 페르소나 등)는 처음 쓸 때 짧게 풀어서 설명한다.

## 1단계: 입력 확인

필요한 정보는 세 가지다. 대화에 이미 있으면 다시 묻지 말고 바로 진행한다.

1. **후보**: 비교할 주제/제목/썸네일 문구/훅 (1개도 가능, 보통 2~5개)
2. **플랫폼**: 유튜브 롱폼 / 쇼츠 / 블로그 / 쓰레드 등
3. **타겟**: 누구에게 보여줄 콘텐츠인지 (예: 30대 직장인, 육아맘)

- 후보가 없으면: 주제를 물어보고 후보 3개를 직접 만든 뒤 테스트한다.
- 플랫폼·타겟이 없으면: 후보 내용으로 합리적으로 추정하고, 결과 맨 위에 "타겟을 ○○로 가정했어요"라고 밝힌다. 추정이 불가능할 때만 질문한다.

## 2단계: 가상 시청자 5명 만들기

타겟에 맞춰 5명을 만든다. 구성은 다음 원칙을 따른다 — 모두 타겟 중심이면 결과가 과하게 긍정적으로 나오기 때문이다.

| 역할 | 설명 |
|---|---|
| 핵심 타겟 2명 | 타겟 그룹 안에서 성향이 다른 두 사람 (예: 관심 많은 사람 / 바쁜 사람) |
| 주변 타겟 1명 | 타겟은 아니지만 알고리즘이 추천해줄 만한 사람 |
| 회의적인 사람 1명 | 낚시·과장에 민감하고 쉽게 클릭하지 않는 사람 |
| 무심한 스크롤러 1명 | 관심 없이 피드를 넘기는 사람 (0.5초 안에 판단) |

각자 한 줄 프로필로 소개한다: `이름(나이, 상황) — 이 사람이 콘텐츠에서 원하는 것`

## 3단계: 반응 시뮬레이션

각 시청자가 **각 후보**를 피드에서 처음 봤다고 상상하고 평가한다.

- **첫 반응**: 그 사람 말투로 한 줄 (예: "또 이런 거야? 넘김")
- **클릭 확률**: 0~10점
- **이유**: 끌린 점 또는 넘긴 이유 한 줄

현실적으로 채점한다. 실제 피드에서는 대부분의 콘텐츠가 그냥 지나쳐진다.
모든 후보에 7점 이상을 주고 싶어진다면 기준이 느슨해진 것이니 다시 본다.
점수 차이가 나야 비교가 의미 있다.

## 4단계: 결과 보고

아래 형식을 그대로 사용한다.

```
## 🎯 가상 시청자 반응 테스트 결과
(가정: 플랫폼 ○○, 타겟 ○○)

### 👥 가상 시청자
1. ... 
(5명)

### 📊 점수표
| 후보 | 시청자1 | 시청자2 | 시청자3 | 시청자4 | 시청자5 | 평균 |
|---|---|---|---|---|---|---|

### 💬 대표 반응
- 후보 A: "..." (시청자 이름)
(후보별로 가장 인상적인 반응 1~2개)

### 🏆 추천: 후보 ○
- 이기는 이유: ...
- 약점: ...

### ✨ 개선안
- 1위 후보를 더 좋게 고친 버전 1~2개와 무엇을 바꿨는지
- (선택) 2위 후보의 장점을 섞은 버전

### ⚠️ 참고
AI가 상상한 반응이라 실제 결과와 다를 수 있어요. 최종 판단은 실제 데이터(조회수, 클릭률)로 확인하세요.
```

- 평균이 같거나 1점 이내로 비슷하면 "박빙"이라고 말하고, 타겟(핵심 타겟 2명) 점수가 높은 쪽을 추천한다. 채널 성장의 핵심은 타겟의 반응이기 때문이다.
- 후보가 1개뿐이면 점수표 대신 "통할까?"에 대한 판정(통함 / 애매함 / 약함)과 개선안 3개를 준다.

## 5단계: 다음 단계 안내

결과 끝에 한 줄로 다음 행동을 제안한다. 사용자가 이미 쓰고 있는 스킬과 연결한다.

- 유튜브 롱폼 → "이 제목으로 대본을 만들까요?" (youtube-script-creator / youtube-automation-pro)
- 쇼츠 → youtube-shorts-automation
- 썸네일 문구 → thumbnail-creator
- 블로그 → seo-blog-creator
- 쓰레드 → threads-content-creator

## 한계

- 이 스킬은 AI의 추론이며 실제 통계가 아니다. 결과를 "예측"이 아닌 "사전 점검"으로 표현한다.
- 수천 명 규모의 여론 흐름이나 시간에 따른 확산을 보고 싶다면 MiroFish 같은 시뮬레이션 도구가 필요하다고 안내한다.
